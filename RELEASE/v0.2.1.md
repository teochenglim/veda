# RELEASE v0.2.1 — Patch

**Status:** ready (test-only fix, no behavior change)
**Theme:** fix the flaky worker test that failed CI on v0.2.0.

## Release notes

### Fixed
- `TestAC5_WorkerRetriesAfterLLMFailure` (and the same latent race in
  `TestAC5_WorkerWithLLMCreatesMemories`) could run the worker's WAL drain
  before the async writer flushed, leaving the pass empty — so the
  LLM-failure test saw no error and failed. Both tests now flush the WAL
  (`w.Close()`) before `RunOnce`, matching the first AC5 test.
  Product code is unchanged: in production the worker ticks 15 minutes after
  any capture, so appends are long since flushed.

## Verification
`go test ./internal/worker/ -race -count=25` passes; full suite green;
`make smoke` OK.

## No AC changes
All v0.1.0 and v0.2.0 acceptance criteria and their tests are unchanged.
