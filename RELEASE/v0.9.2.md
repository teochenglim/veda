# RELEASE v0.9.2 — Patch

**Status:** ready (CI-only fix, no behavior change)
**Theme:** release binaries now carry their version string.

## Release notes

### Fixed
- The release workflow's **Build binary** step stamped
  `-X main.version=${VERSION}` but never had `VERSION` in its `env:` (only
  `GOOS`/`GOARCH`/`CGO_ENABLED`), so every published archive was built with
  an **empty version string**. Caught by the v0.9.1 `smoke-install` job:
  the install itself succeeded, but `veda version` printed `veda ` instead
  of `veda v0.9.1`, failing the comparison. The build step now sets
  `VERSION: ${{ github.ref_name }}`.

### Notes
- The smoke job ran on the right runners (ubuntu/macos-latest) and did
  exactly its job — the macos leg was cancelled by matrix fail-fast, not a
  VM problem.
- Not retroactive: archives for v0.1.0–v0.9.1 report an empty version.
  `make build` (local) was never affected — it stamps from the VERSION file.

## Verification
Workflow YAML parses; `semgrep` clean; full test suite green; `make smoke`
OK. The fix is proven by the next `smoke-install` run on the v0.9.2 tag.

## No AC changes
All v0.1–v0.9.1 acceptance criteria and their tests are unchanged.
