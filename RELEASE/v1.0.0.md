# RELEASE v1.0.0 — UOMP 1.0: freeze, second implementation, governance

**Status:** planned — the standard becomes real because something other
than Veda implements it.

**Theme:** "Like Chrome is the product, HTTP is the spec." At 1.0, UOMP is
no longer a description of Veda — Veda is one implementation of UOMP.

## Scope (planned)

### The freeze
- UOMP 1.0 promotes draft-01 + draft-02 to a frozen 1.0.0 spec
  (`spec/uomp-1.0.md`): on-disk schema, export format, MCP tool contract,
  sync wire format.
- **Stability guarantees** (`spec/VERSIONING.md` final):
  - Export format is readable forever — no breaking change, ever.
  - Tool contract is additive-only within 1.x (new optional params/tools).
  - Sync wire: additive headers/fields; breaking changes require UOMP 2.0.
  - Deprecations ship one minor before removal, with warnings.

### Second implementation (the compatibility proof)
- **`uomp-kit`**: a minimal second implementation (TypeScript or Python,
  community/reference repo) covering: reading a UOMP export, speaking the
  five tools over stdio, and pushing/pulling a sync bundle. Kept honest by
  CI: `uomp-kit` runs the `veda conformance` suites on every change to
  either repo.
- **Interop matrix in CI**: Veda ↔ spec conformance, uomp-kit ↔ spec
  conformance, Veda ↔ uomp-kit cross-ops (Veda reads a uomp-kit export,
  uomp-kit pulls from a Veda-synced endpoint stub).

### Governance
- `spec/GOVERNANCE.md`: spec changes by RFC (`spec/rfcs/`), two-implementation
  rule for any new normative feature, backward-compatibility charter.

### Launch
- UOMP 1.0 announcement alongside the v1.0.0 tag; conformance suite
  published as a standalone artifact so third parties can self-certify.

## Acceptance criteria (planned)

| # | Criterion | Test (to add) |
|---|---|---|
| AC1 | `uomp-kit` passes the full `veda conformance` suite in CI, in both directions | CI interop job |
| AC2 | Veda passes conformance against its own releases back to v0.8 (no silent drift) | CI matrix job |
| AC3 | Veda reads an export produced by uomp-kit; uomp-kit reads a Veda export | interop test |
| AC4 | Governance docs merged; every normative spec feature names two implementations | spec review |
| AC5 | v1.0.0 tagged; spec + conformance artifacts attached to the GitHub release | release workflow |

## Deliberately not in 1.0
New product features. 1.0 is a stability statement: everything shipped in
v0.1–v0.8 keeps working, unchanged, for the life of UOMP 1.x.

## Post-1.0 candidates (not committed)
Spec 1.1 additive extensions (new optional tools, richer policy formats),
spec 2.0 discussion only if a genuinely breaking need emerges.
