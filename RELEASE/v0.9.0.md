# RELEASE v0.9.0 — UOMP draft-02 (MCP tool contract + sync wire)

**Status:** planned — not implemented yet.

**Theme:** freeze the wire. After this release, anything that speaks the
five tools or the sync bundle contract can be tested against the standard,
not against Veda.

## Why this split

Draft-01 (v0.8.0) covers data at rest. Draft-02 covers data in motion: the
MCP tool interface every agent programs against, and the sync bundle
contract every backend implements. Both are already stable in practice —
the tool contract has not changed shape since v0.1, and the sync wire since
v0.4 — so this release is codification plus the machinery to prove it.

## Scope (planned)

### Added
- **UOMP draft-02** (`spec/uomp-draft-02.md`), normative for:
  - **Tool contract**: `remember`, `recall`, `list`, `forget`, `export` —
    input schemas, defaults (`limit=5`, `min_confidence=0.5`), semantics
    (soft delete + audit, supersession visibility rules), and error
    behavior. Includes the additive extensions (`semantic`,
    `include_superseded`) marked as optional-to-implement.
  - **Sync wire**: envelope format, bundle payload, the two REST verbs,
    `402` paid-gate semantics, and the change-log watermark rule.
- **`veda conformance tools --command <cmd>`**: drives *any* MCP server
  over stdio with the in-memory client and scores it against the tool
  contract — this is how a second implementation will be certified in v1.0.
- **`veda conformance sync --endpoint <url>`**: validates a backend
  against the wire contract (ingest, since_id paging, device exclusion,
  402 propagation).
- **Golden vectors** (`spec/vectors/`): canonical export document, a signed
  audit export with fixed test keys, and fixed-key sync envelope round
  trips — so implementations can test offline.
- **Deprecation policy** (`spec/DEPRECATIONS.md`): any delta between the
  draft and current behavior ships as a warning first; nothing breaks in
  the same release that documents it.

### Changed
- Anywhere the implementation disagrees with the draft, the implementation
  changes (with a deprecation warning if externally visible).
