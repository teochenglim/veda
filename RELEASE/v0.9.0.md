# RELEASE v0.9.0 — UOMP draft-02 (MCP tool contract + sync wire)

**Status:** implemented (client side; tests enforce the ACs below)

**Theme:** freeze the wire. After this release, anything that speaks the
five tools or the sync bundle contract can be tested against the standard,
not against Veda.

## Why this split

Draft-01 (v0.8.0) covers data at rest. Draft-02 covers data in motion: the
MCP tool interface every agent programs against, and the sync bundle
contract every backend implements. Both are already stable in practice —
the tool contract has not changed shape since v0.1, and the sync wire since
v0.4 — so this release is codification plus the machinery to prove it.

## Release notes

### Added
- **UOMP draft-02** ([spec/uomp-draft-02.md](../spec/uomp-draft-02.md)),
  normative for:
  - **Tool contract** (§2): `remember`, `recall`, `list`, `forget`,
    `export` — input schemas, defaults (`limit=5`, `min_confidence=0.5`),
    semantics (soft delete + audit, supersession visibility, unknown-id
    `deleted:false`), and error behavior. The additive extensions
    (`semantic`, `include_superseded`) are marked optional-to-implement.
  - **Sync wire** (§3): the two REST verbs, server-assigned monotonic ids,
    device exclusion, `since_id` paging, envelope + fixed crypto parameters
    (XSalsa20-Poly1305, scrypt N=32768/r=8/p=1), Bearer auth, the **402
    paid-gate** semantics, and the change-log watermark rule (cursor =
    sequence, never wall-clock; advance only after a successful merge).
- **`veda conformance tools --command <cmd>`**: drives any MCP server over
  stdio with the go-sdk client and scores it against §2 — fourteen named
  checks from catalog to unknown-tool error. This is how a second
  implementation gets certified in v1.0.
- **`veda conformance sync --endpoint <url> [--token T] [--unpaid-token T]`**:
  validates a backend against §3 — monotonic ingest, device exclusion,
  since_id paging, envelope wire shape + decryption fidelity, auth gate,
  and (with `--unpaid-token`) the 402 gate.
- **`ReferenceBackend`** (`internal/conformance`): an in-memory executable
  reference implementation of the wire contract — the fixture the suite is
  validated against and a starting point for backend authors.
- **Golden vectors** (`spec/vectors/`): canonical draft-01 export document,
  a signed audit export under a committed test-only Ed25519 key, and a
  fixed-key sync envelope (fixed passphrase/salt/nonce ⇒ byte-deterministic)
  — implementations test offline and across versions. Regenerate with
  `VEDA_UPDATE_VECTORS=1 go test ./internal/conformance -run
  TestGenerateVectors`.
- **Deprecation policy** ([spec/DEPRECATIONS.md](../spec/DEPRECATIONS.md)):
  deltas ship as warnings first; nothing breaks in the release that
  documents them. Register currently empty.

### Changed
- Nothing. Draft-02 matches shipped behavior exactly — no deprecation
  warnings were needed (AC5 is the standing gate that keeps it that way).

## Acceptance criteria

| # | Criterion | Test |
|---|---|---|
| AC1 | `veda conformance tools` passes against veda itself over stdio | `conformance.TestAC1_ConformanceToolsPassesVeda` (real `mcpserver.New` layer in a helper process) |
| AC2 | `veda conformance tools` fails a deliberately broken stub server (wrong forget semantics) with the violated rule named | `conformance.TestAC2_ConformanceToolsFailsBrokenStub` |
| AC3 | `veda conformance sync` passes against the reference fake backend | `conformance.TestAC3_ConformanceSyncPassesReference` |
| AC4 | Golden vectors: a fixed-key envelope round-trips across versions; the signed audit vector verifies | `conformance.TestAC4_GoldenVectors` |
| AC5 | Draft-02 documents every delta from current behavior; no undocumented drift | `conformance.TestAC5_NoUndocumentedDrift` (storage + tools + sync self-conformance + DEPRECATIONS.md present) — runs in every CI run |
| AC6 | All v0.1–v0.8 AC tests remain green | `make vet test` |

Supporting tests: an open (auth-less) endpoint fails sync conformance with
the rule named (`TestSyncConformanceFailsOpenEndpoint`).
