# RELEASE v0.7.0 — Team compliance: signed audit export + org policies

**Status:** implemented (tests enforce the ACs below)
**Theme:** prove what happened to memories over time — and make house rules enforce themselves.

## Release notes

### Added
- **Signed audit export**: `veda audit keygen` (Ed25519, private key 0600
  in `~/.veda/audit_signing_key`), `veda audit export` (the complete audit
  log — create/update/forget/supersede/resolve/retention — signed over the
  exact payload bytes, public key embedded), and `veda audit verify -f
  export.json` for reviewers. Any alteration fails loudly:
  `SIGNATURE INVALID — this export has been altered`.
- **Org policies** via a `[policies]` config section:
  - `retention_days` — memories older than N days are soft-deleted,
    tombstoned (propagates to synced devices), vector-invalidated, and
    audited per record (`action=retention, actor=policy`). Enforced at
    `serve`/`worker` start and via `veda policy enforce`.
  - `redact` — regex patterns scrubbed to `[redacted]` on every write path
    (`remember`, WAL-turn capture, worker distillation, UI approval);
    redacted memories are visibly marked `type += " redacted"`. Bad regexes
    fail startup naming the pattern.
- **`veda policy status | enforce`** — inspect active policies, run the
  retention sweep on demand.
- Paid tier: orgs obtain managed `[policies]`-stamped configs and
  long-term export storage from the organization backend (separate repo,
  same 402 pattern as sync/benchmarks). Local enforcement is complete
  without it.

### Defaults
No `[policies]` section ⇒ byte-identical v0.6 behavior: no scrubbing, no
sweeps (AC5).

## Acceptance criteria

Every AC is a named Go test (`make test`).

| # | Acceptance criterion | Test |
|---|---|---|
| AC1 | keygen → export → verify passes; a single altered byte fails with `SIGNATURE INVALID`; private keys persist 0600 | `audit.TestAC1_KeygenSignVerifyTamper` |
| AC2 | Exports are complete: every action type (create/forget/supersede/resolve) present, install id embedded | `audit.TestAC2_ExportCompleteness` |
| AC3 | Retention retires only pre-cutoff memories — soft delete + tombstone + per-record audit — idempotently | `store.TestAC3_RetentionEnforcement` |
| AC4 | Redaction patterns scrub `remember` and captured turns; type is marked | `store.TestAC4_RedactionOnWrites` |
| AC5 | No `[policies]` config ⇒ v0.6-identical behavior; bad regexes named at startup | `store.TestAC5_PoliciesDefaultOff` |
