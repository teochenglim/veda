# RELEASE v0.6.0 — Advanced eval harness (paid, the moat)

**Status:** planned — moved here from v0.5.0 so the telemetry-audit release
could ship on its own.

**Theme:** measure recall the way users experience it — and prove distillation
didn't make things up.

## Scope (planned)

### Added
- **Scenario format**: fixture files describing seed conversations /
  memories plus expected recalls (query, `expect_contains`,
  `expect_not_contains`, top-k, min confidence).
- **`veda eval`**: runs a suite against a **throwaway store** (never the
  user's real `~/.veda`), scores recall@k pass rates, and exits non-zero on
  failure — CI-friendly. `--report out.json` emits machine-readable
  per-case results.
- **Interference detection**: ingest "disruptor" memories mid-suite and
  measure how much recall of previously-correct queries degrades.
- **Faithfulness scoring**: token-attribution score for each distilled
  memory against its source turns; flags memories the LLM invented.
- **Paid tier (cross-install benchmarks)**: `veda eval --upload-url`
  posts anonymized aggregate reports (pass rates, scores — no memory
  content) to the benchmark backend for cross-install ranking. Same 402
  paid-gate pattern as sync; the backend ships in a separate repo.

## Acceptance criteria (planned)

| # | Criterion | Test (to add) |
|---|---|---|
| AC1 | Scenario files load; malformed ones fail with actionable errors | `eval` parser test |
| AC2 | Seeding + recall scoring: pass and fail cases scored correctly against a throwaway store | `eval` runner test |
| AC3 | Interference detection reports degradation when disruptors are ingested (and none for benign ones) | interference test |
| AC4 | Faithfulness scoring flags memories not attributable to source turns | faithfulness test |
| AC5 | Isolation: running eval never mutates the user's real store | isolation test |
| AC6 | `--upload-url` handles 402 as the paid gate (client side) | upload hook test |
