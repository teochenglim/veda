# RELEASE v0.9.1 — Patch

**Status:** ready (CI-only fix, no behavior change)
**Theme:** unblock release CI — fix the two semgrep blocking findings.

## Release notes

### Fixed
- Release CI failed semgrep (`github-actions.security.run-shell-injection`):
  the `smoke-install` and `smoke-brew` jobs interpolated `${{ github.ref_name }}`
  and `${{ vars.HOMEBREW_TAP }}` directly into `run:` scripts.
  Workflow context data is treated as attacker-controllable, so the values now
  pass through `env:` and are quoted in the script (`"$VEDA_VERSION"`,
  `"$HOMEBREW_TAP"`) — identical expressions, no textual substitution into the
  shell (a ref name with shell metacharacters can no longer execute).

## Verification
`semgrep scan` with the exact CI rule set (`p/golang`, `p/sql-injection`,
`p/secrets`, `p/owasp-top-ten`): 0 findings, exit 0. All workflow YAMLs parse;
full test suite green; `make smoke` OK.

## No AC changes
All v0.1–v0.9.0 acceptance criteria and their tests are unchanged. This is a
`.github/workflows/release.yml`-only patch.
