# RELEASE v0.8.0 — Distribution + UOMP draft-01 (storage & export formats)

**Status:** implemented (client side; tests enforce the ACs below)
**Theme:** installable everywhere, and the first half of the UOMP standard
published: what a Veda-compatible store looks like on disk, and what an
export document means.

## Why this split

v1.0.0 (UOMP 1.0) bundles four freezes: on-disk schema, export format, MCP
tool contract, sync wire format — plus a second implementation and
governance. Doing all of that in one release would make draft feedback
impossible. v0.8.0 publishes the storage half alongside the distribution
work that a standard needs anyway (people can't adopt a spec they can't
install).

## Release notes

### Added
- **Distribution**: `install.sh` (curl-able; wraps the GitHub release
  archives, verifies SHA-256 against the release's `SHA256SUMS`, installs to
  `/usr/local/bin` or `~/.local/bin`), a Homebrew formula and a Scoop
  manifest rendered from those same checksums by `make packaging
  VERSION=x.y.z`, and a `smoke-install` release-CI job on clean
  macOS/Linux runners. The release workflow now publishes `SHA256SUMS` for
  every archive it builds.
- **UOMP draft-01** ([spec/uomp-draft-01.md](../spec/uomp-draft-01.md)):
  normative description of 1. the on-disk SQLite schema (tables, FTS mirror
  + triggers, tombstones, change log) and 2. the export format v1 (exact
  JSON shape produced by `veda export` and consumed by `veda import`),
  plus the signed audit envelope from `veda audit export`.
- **`veda conformance storage [--dir <veda-home>]`**: read-only draft-01
  validation — `db-open`, `schema-tables`, `schema-columns`, `fts-triggers`,
  `fts-sync`, `export-shape` — every failure names its reason. The new
  `internal/conformance` package exposes `RunStorage` (directory report) and
  `ValidateExport` (export-document violations) for reuse.
- **Spec versioning policy** ([spec/VERSIONING.md](../spec/VERSIONING.md)):
  draft → 1.0 freeze; additive changes in minor versions; breaking changes
  require a major and a migration note.

### Changed
- `veda export` now emits `memories`/`turns`/`audit` as `[]` when empty
  instead of `null` — draft-01 requires arrays, and the draft must describe
  reality. The only behavioral change in this release, found while
  codifying. Imports are unaffected (Go treats `null` and `[]` identically).

### Conformance notes (for reviewers of the draft)
External-content FTS5 answers `COUNT(*)` and full scans through the content
table, and FTS5's `integrity-check` does not cover external content — so
neither can detect mirror drift. `fts-sync` therefore verifies the invariant
with the `%_docsize` shadow table (cardinality) and per-row `MATCH` phrase
probes (content alignment), the two views that actually read the index.
`spec/uomp-draft-01.md` §2.3 documents this for other implementers.

## Acceptance criteria

| # | Criterion | Test |
|---|---|---|
| AC1 | `brew install` from the tap works on a clean macOS runner | `release.yml` `smoke-brew` job (enabled by setting the `HOMEBREW_TAP` repo variable; tap/bucket publication is a launch task) |
| AC2 | `install.sh` installs a working veda on clean ubuntu/macos runners | `release.yml` `smoke-install` job |
| AC3 | `veda conformance storage` validates a store created by v0.7.0 as draft-01 compliant | `conformance.TestAC3_ConformanceValidatesV07Store` |
| AC4 | An export document produced by v0.7.0 validates against the draft-01 export schema | `conformance.TestAC4_ExportMatchesDraft01Shape` |
| AC5 | A deliberately corrupted store (missing trigger, drifted FTS) fails conformance with the reason named | `conformance.TestAC5_CorruptStoreFailsNamed` |
| AC6 | All v0.1–v0.7 AC tests remain green (no contract drift while codifying) | `make vet test` |
