# RELEASE v0.1.0 — MVP

**Status:** shipped (this repo, initial release)
**Theme:** *One local memory file. Every MCP agent reads and writes it. Your machine, your key, your DB.*

## What's in

1. Single static Go binary (`CGO_ENABLED=0`), SQLite via `modernc.org/sqlite`
   (pure Go — FTS5 included, no C toolchain on any platform).
2. MCP server over stdio built on the official Go SDK
   (`github.com/modelcontextprotocol/go-sdk` v1.8.0), input schemas inferred
   from Go structs.
3. Write-ahead log (`~/.veda/wal.ndjson`): buffered async appends, atomic
   rotate-on-drain.
4. Cheap gate: role check, 16–2000 byte length window, secret-pattern veto,
   first-person signal regexes → candidate score.
5. Worker pipeline: drain → gate → pending queue → batch summarize via any
   OpenAI-compatible endpoint using a key from the environment
   (`VEDA_LLM_API_KEY` by default). Also runnable one-shot: `veda worker`.
6. Embedded review UI (no external assets) at `127.0.0.1:7331`.
7. Telemetry: opt-in only, counts-only payload with `veda telemetry preview`,
   24h flush loop while `serve` runs, DELETE-based erasure
   (`veda telemetry forget`). The Cloudflare Worker backend is a separate
   repository; the URL is user-configured in `config.toml`.
8. Export/import as portable JSON.
9. CI (vet + race tests) and release pipeline (6-platform archives → GitHub
   Release) via GitHub Actions; `make release VERSION=x.y.z`.

## What's explicitly out (per PRD)

Vector search · cross-agent conflict resolution · hosted sync · eval harness
· encryption beyond OS-level · multi-user · mobile · any auto-consent
telemetry.

## Known limitations

- Recall is lexical (FTS5), not semantic — "coffee habits" won't match
  "caffeine rules". Semantic search lands in v0.2.
- The gate is deliberately over-trigger-y; the human review loop is the
  quality control.
- `serve` handles tool calls concurrently; clients that pipeline calls
  without reading responses may observe their own race (writes and reads are
  individually atomic but unordered). Standard clients are sequential.
- Telemetry endpoint URL is empty by default until the worker repo ships.
