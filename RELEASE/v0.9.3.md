# RELEASE v0.9.3 — Patch

**Status:** ready (toolchain floor bump, no behavior change)
**Theme:** clear the Go 1.27.1 standard-library advisories flagged by `govulncheck`.

## Release notes

### Security
- `go.mod` now requires **Go 1.27.2** (was 1.27.1). The security workflow
  resolves its toolchain from `go.mod`, so it was building against 1.27.1 and
  reporting stdlib advisories reachable from veda's HTTP client/server,
  TLS and TOML-write paths:
  - GO-2026-6617 — HTTP/2 server crash due to HPACK encoder race (`net/http`)
  - GO-2026-6607 — `crypto/tls` fix
  - GO-2026-6605 — HTTP/1 client connection desync after CONNECT rejection (`net/http`)
  - GO-2026-6603 — HTTP/2 server memory exhaustion via Trailer headers (`net/http`)
- All four are fixed in Go 1.27.2; no veda source changes were needed.

### Notes
- Release/CI workflows use `GO_VERSION: '1.27'`, which `setup-go` resolves to
  the latest 1.27.x, so they pick up the patched toolchain too.
- Anyone building from source needs Go ≥ 1.27.2.

## Verification
`make vet test` green on go1.27.2. Re-run `govulncheck ./...` (security workflow) to confirm the advisories clear.

## No AC changes
All v0.1–v0.9.2 acceptance criteria and their tests are unchanged.
